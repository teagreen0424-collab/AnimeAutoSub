## 3. 三档重跑行为审计与 G1a 缺陷修复契约 (F4 结论)

- **当前代码的缺陷机制**:
  `pipeline.py` 与 `pipeline_ocr.py` 在每个阶段仅简单使用 `if file.exists(): skip` 判定。
  导致一旦用户修改了 `SUBTITLE_FONTSIZE`、遮罩样式或修改了翻译提示词，重新执行流水线时直接触发全部 skip，**输出成片完全不更新**。
- **G1a 阶段重构契约**:
  必须废除 `if exists: skip` 粗暴逻辑，引入**基于 DAG 上游产物哈希与配置参数签名的脏检查机制（Dirty Check）**：
  - **档位 a (改字号/遮罩)**: 检查到排版配置改变，自动使 `subtitle.ass` 及下游视频文件失效，精准重跑 `Layout -> Mux -> Render`。
  - **档位 b (改翻译参数)**: 检查到 Prompt/词表变化，使 `chinese.json` 及全部下游失效，精准重跑 `Translate -> Layout -> Mux -> Render`。
  - **档位 c (全新工作区)**: 纯净冷启动全量执行。

    - Pass 2 vs Pass 3: 差异帧数 = 0/100, 编辑距离 = 0, CER = 0.0000%

  - **科学结论与门禁降级**:

### 4.2 PO 输入动态宽度假设验证：固定 Padding (960px) 对照实测 (H2)
- **科学假设**: Rec 模型输入宽度随文本长度动态变化，导致不同 shape 频繁触发 cuDNN 重新寻找/编译卷积算法，解释了 Pass 1 与 Pass 2 的 6 倍耗时差。
- **实验测法**: 将 Rec 输入图像在预处理阶段统一右侧补零 Padding 到固定宽度 `960px`（固定输入张量 shape 为 `[1, 3, 48, 960]`）。
- **实测数据对比**:
  - **Pass 1 耗时**: 原生动态 = **130.60s** vs 固定 Padding = **40.94s**（**耗时暴跌 68.7%！单帧平均从 1306ms 降至 409ms！**）
  - **Pass 2 稳态耗时**: 原生动态 = **19.71s** vs 固定 Padding = **21.28s**（稳态水平完全一致）
  - **识别差异**: 差异帧数 = 0/100, CER = 0.0000%
- **核心推论**: **PO 的假设得到 100% 实验证实**！Pass 1 的首轮延迟完全是由输入宽度动态变化引起的 cuDNN 动态算子编译所致；固定 Padding 成功消除了绝大多数重复编译开销！

### 5.2 废除理论过度余量，实测标定租约门禁红线
- **旧公式缺陷**: 原理论公式 `free >= 6054 * 1.05 + 400 = 6757 MiB`，在典型空闲 6635 MiB 下导致主用例被永久阻断。
- **新门禁判据（以实测为准）**:
  - 实测模型常驻净显存: `6086 MiB`
  - 动态推理 KV Cache 最小安全缓冲: `250 MiB`
  - **真实物理启动门槛**:
    $$\text{Required\_Free\_VRAM} \ge 6086 + 250 = \mathbf{6336\text{ MiB}} \approx \mathbf{6350\text{ MiB}}$$
  - **调度判定**:
    只要可用空闲显存 `free_vram >= 6350 MiB`，即判定显存安全，允许申请 GPU 租约启动翻译；若 `free_vram < 6350 MiB`，抛出显存不足明确告警并拒绝启动。此门限完美保障在正常 IDE 与桌面底噪（$\le 1838\text{ MiB}$）下主用例畅通执行。

### 5.3 严格互斥串行租约 (Strict Mutual Exclusion)
- 全局并行度强制锁定为 1。
- 租约生命周期：`Acquire(ModelName) -> Assert(Free_VRAM >= Threshold) -> Run -> Release(Explicit GC & Empty Cache / ollama stop)`。
- 严禁任何两个计算模型在显存中重叠停留。
