# AnimeAutoSub · 结构搬迁确定性回归测试规范 (SPEC_PARITY.md)

> **文档状态**: 冻结生效 (依据 PO G3 指令完成哈希降级修订)  
> **制定版本**: v1.1  
> **核心宗旨**: 验证从 Legacy 单体脚本向模块化重构过程中的**行为一致性（Parity）**。确保重构不改动任何数学/排版/音频逻辑。

---

## 1. 核心设计原则

### 1.1 LLM 阶段物理隔离原则 (LLM Isolation)
- **物理事实**: 任何大语言模型（包括 Sakura-14B、Qwen-2.5 等）在本地推理时，受量化核函数并行排布、浮点舍入微小抖动及 Ollama 调度机制影响，在温度非零或批量变化时难以保证 100% 逐 token 恒等。
- **门禁纪律**: **Parity 测试严禁将在线大模型作为端到端断言项**。
- **分界隔离机制**:
  - **上游测试（阶段 1 ~ 3 / OCR 阶段 1）**: 真实运行，断言产出的 `japanese.json` 或 `vocals.wav` 与参照一致。
  - **下游测试（排版与封装）**: **切断在线 LLM**，强制将冻结在 `bench/fixtures/reference/` 下的 `chinese.json` 作为下游输入，验证排版器生成的 `subtitle.ass` 与渲染帧像素的一致性。
  - **LLM 独立测试**: 由独立的确定性测试脚本（`test_translator_contract.py`）单测 Sakura API 的契约（Schema、占位符保留、重试与熔断机制）。

### 1.2 门禁分级原则 (G3 指令修订：精确哈希降级)
- **历史问题**: 依赖 SHA256 逐字节匹配或 `CER == 0.00%` 作为硬性阻断，在底层驱动微小变动、CUDA 算子浮点舍入抖动或排版头时间戳格式变动时极易误报假失败，导致测试脆弱。
- **两级度量规范**:
  - **硬门禁 (Hard Gate / Blocking)**: 逻辑语义与物理指标恒等判定。
    1. **条目数量一致**: `len(actual) == len(reference)`。
    2. **逐行文本归一化完全相等**: 经过标准空白修剪与 Unicode 字符归一化（NFKC）后必须逐行 100% 一致。
    3. **时间戳容差门禁**: 起始与结束时间戳偏差 $|\Delta t| \le 40\text{ms}$（对应约 1 帧画面时长）。
    4. **ASS 核心结构一致**: 事件行数一致、Style 配置一致、遮罩图形顶点坐标一致。
  - **观测项 (Observation Metric / Non-blocking)**: 记录并报告指标漂移，不阻断流水线。
    1. **SHA256 哈希值**: 计算并输出完整散列值，仅供追踪变更来源，不作为判定通过/失败的依据。
    2. **CER (Character Error Rate)**: 输出字符错误率百分比，用于衡量极端情况下的模型退化风险。

## 2. 逐阶段断言判据 (Stage Parity Assertions)

### 2.1 语音流 (Chain A - Audio ASR)

| 阶段 | 产生工件 | 硬门禁 (Blocking Fail) | 观测项 (Logged Only) |
| :--- | :--- | :--- | :--- |
| **Stage 1: 取音** | `audio.wav` | 16000Hz, 单声道, s16le, 长度误差 $\le 40\text{ms}$ | SHA256 |
| **Stage 2: 分离** | `vocals.wav` | 采样率 16000Hz, RMS 能量差 $\le 0.5\%$ | SHA256 |
| **Stage 3: 转写** | `japanese.json` | 1. 句子条目数量严格一致<br>2. 逐句文本 NFKC 归一化后 100% 相等<br>3. 起止时间戳偏差 $\le 40\text{ms}$ | 1. SHA256<br>2. CER 指标 |
| **Stage 4: 翻译** | *(隔离阶段)* | 仅校验 Schema 完整性与 JSON 合法性，跳过哈希比对 | Token 统计 |
| **Stage 5: 打轴** | `subtitle.ass` | 1. Events 条数严格一致<br>2. 逐行 Dialogue 样式与归一化内容完全相同<br>3. 时间轴误差 $\le 40\text{ms}$ | SHA256 |
| **Stage 6: 封装** | `_中文字幕.mkv` | 提取字幕轨，Dialogue 行与 `subtitle.ass` 100% 相同 | 封装流元数据 |
| **Stage 6: 压制** | `_中文字幕.mp4` | 3 组基准帧非文字区像素差 = 0，文字区 PSNR > 38dB | 压制码率与耗时 |

### 2.2 画面硬字幕流 (Chain B - Video OCR)

| 阶段 | 产生工件 | 硬门禁 (Blocking Fail) | 观测项 (Logged Only) |
| :--- | :--- | :--- | :--- |
| **Stage 1: OCR** | `japanese.json` | 1. 聚合条目数偏差 $\le 3\%$<br>2. 噪声底驱动门禁：差异行数 $\le 5\%$ 且整体 $\text{CER} \le 15\%$ (P6 校准目标)<br>3. 时间轴聚合区间偏差 $\le 40\text{ms}$<br>4. **采样中点帧规则 (P2)**：杜绝首尾过渡帧，取连续 $\ge 2$ 帧相似度 $\ge 0.80$ 平原区几何中点帧 | 1. SHA256<br>2. 逐行差异明细记录<br>3. 归档：时序投票无效机理 (P1) |
| **Stage 2: 翻译** | *(隔离阶段)* | 注入固化 `chinese.json` 隔离 LLM 随机性 | 契约验证 |
| **Stage 3: 排版** | `subtitle.ass` | 1. Dialogue 条数一致<br>2. Mask 矩形绘制参数 (`\p1 m ...`) 坐标误差 $\le 1\text{px}$<br>3. 逐行翻译文字归一化完全相等 | SHA256 |
| **Stage 4: 渲染** | `_中文字幕.mp4` | 3 组基准关键帧非遮罩区域像素差 = 0，画面整体 SSIM > 0.98 | 压制码率与耗时 |

> [!NOTE] P1 ~ P5 专项工程决议归档 (Hardsub OCR Stabilization)
> 1. **时序多数投票（Majority Voting）废止 (P1)**：经 15 帧短集与 12 帧长集全量实测，时序投票相比稳定中点帧未产生正收益（26 帧中有 25 帧完全一致，1 帧甚至恶化），判定失败。**机理**：同一字幕区间内相邻帧的文字形变、背景干扰与解码失真高度同向，帧间误差非独立随机分布，多数投票无法消除同向系统误差。代码已移入 `bench/` 归档，严禁进入生产代码。
> 2. **稳定平原区中点帧物理规则与基线重锚 (P2 / Q2)**：
>    - **物理规则**：在 `pipeline_ocr.py` 的抽帧聚合中，严禁取区间首帧或尾帧（存在淡入淡出半透明残片与残缺字）。必须通过 `select_stable_midpoint_text` 在连续相似度 $\ge 0.80$ 的稳定平原区（plateau $\ge 2$ 帧）选取几何中点帧识别文本。若无稳定平原区，则退回全局时间中点帧。
>    - **基线锁定**：**P2 是唯一产生实质收益的改动**。短集基线从 98 (22.32%) 降至 68 (15.49%，净降 -6.83pt / 30 处编辑)；长集基线从 51 (16.09%) 降至 42 (13.25%，净降 -2.84pt / 9 处编辑)。**后续所有对比必须以 P2 之后的基线 (短集 68 / 长集 42) 为准，严禁再引用 98 / 51 旧数**。
> 3. **det 2x 上采样 + Y 轴聚类判定为负结果 (P5 / Q1)**：
>    - 实测数据：短集 15 帧 baseline 68 (15.49%) → p5 65 (14.81%)，仅微降 +0.68pt（3 字符，在抽样误差内）；长集 12 帧 baseline 42 (13.25%) → p5 52 (16.40%)，严重恶化 -3.15pt（-10 字符，复杂背景过度分割碎屑噪点）。
>    - **结论与纪律**：**det 2x 上采样 + Y 轴聚类在本素材上无效/有害**，整体判定为负结果，不许计入收益，相关脚本已标注 `REJECTED` 归档，严禁合入生产流水线。
> 4. **基准门禁现状重述 (P6 / Q3)**：
>    - 彻底收回“打穿 15% 门禁”的非严谨表述。
>    - **客观事实**：P2 之后短集 15.49%、长集 13.25%，处于 13%~15.5% 震荡区间；P5 实验长集 16.40% 且未带来统计显著改善。
>    - **门禁纪律**：后续若要宣称硬字幕 CER 达标 $\le 15\%$，必须先将短集样本扩充至 $\ge 40$ 帧、长集扩充至 $\ge 25$ 帧，取得统计显著性后方可申报。
> 5. **自适应遮罩几何替代全宽黑条 (R1 规范)**：
>    - 废除固定 `MASK_TOP/MASK_HEIGHT` (1920×180 全宽实心矩形，原画遮盖面积 345,600 px)；
>    - 改由每句 OCR 检测框并集 + 8px padding 逐句自适应计算；
>    - 施加 8px 高度网格量化，保证同一场景内遮罩高度方差 $\le 8\text{px}$；
>    - 动态核验中文字幕排版宽度，保证中文不压边；
>    - **验收指标硬断言**：原画遮盖面积平均降至 $\le 120,000\text{ px}$（降幅 > 70%），日文笔画残留率 $\approx 0$。由 `tests/test_adaptive_mask.py` 自动化门禁守护。
> 6. **OCR 推理动态尺寸停顿治理与 HEURISTIC 算法锚定 (U1 规范)**：
>    - 在 RapidOCR 默认配置中，`EngineConfig.onnxruntime.cuda_ep_cfg.cudnn_conv_algo_search` 默认为 `"EXHAUSTIVE"`。当输入尺寸（如检测框数量或长宽比）动态变化时，cuDNN 会触发耗时 1.3s~3.8s 的穷举基准测试评测循环，导致短视频 64.99s 的推理中有 88% 为 shape 评测停顿。
>    - **生产强制断言**：必须显式配置 `cudnn_conv_algo_search = "HEURISTIC"`，通过启发式分析跳过基准测试评测，将 Stage 1 总耗时从 66.7s 骤降至 13.5s（提速 79.8%），单次推理稳态降至 264ms。
> 7. **局部乱码智能切除修复与 127.0.0.1 网络规范 (U2 / U3 规范)**：
>    - **拒识与切除准则 (U2)**：严禁对含有局部 OCR 乱码的好句子进行整句暴力丢弃（防止有效台词缺失）。必须先切除局部乱码片段（大写字母串、符号串、5位以上数字及前后无假名的孤立数字），前后有效文本拼接。仅当有效文本比例 $< 45\%$ 或不足 3 字符时才整句拒识。实测整句拒识率降至 $\le 2.63\%$。
>    - **本地通信网络规范 (U3)**：在 Windows 环境下，`localhost` 会优先解析并尝试 IPv6 `[::1]`，但 Ollama 仅监听 IPv4，导致 Windows TCP SYN 重传超时 2.0 秒。生产环境必须统一使用 `http://127.0.0.1:11434` 并配合 `requests.Session()` 复用连接，彻底消除毫秒级连接之上的 2.0s 伪延迟。
> 8. **旧版时间轴合并吞句缺陷与解构修复 (X1 归因)**：
>    - **吞句机理**：旧版基于固定空格插入与粗暴相似度的合并逻辑，在 10~15 秒长区间存在严重缺陷。当画面在第一位说话人台词结束后紧随出现第二位说话人对白时，第二位说话人的台词极易被前一句的滞留状态吞没。
>    - **解构收益**：新版消除了词间干扰空格，引入稳定平原区切分，成功将 97 个旧超长区间解构拆分出 155 个独立句子，找回了被旧版合并逻辑吞掉的第二个说话人真实对白（如 `恵麻は私と夫のたった一人の娘だ。`、`枝彌「瑛斗もおはよう」` 等）。同时修复了 48 处因帧抖动导致的旧版错误碎句合并。
